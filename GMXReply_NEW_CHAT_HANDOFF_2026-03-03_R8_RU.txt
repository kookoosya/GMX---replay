Продолжаем проект **GMXReply**.

Я приложу:

1. **свежий текущий рабочий архив** — это **единственный source of truth**
2. **последний handoff txt**
3. при необходимости — отдельный архив с **Arcade (React + Vite)** и его txt-инструкции
4. **последний cumulative pack** с файлами на замену

## Главное правило

Если что-то из старых сообщений, старых патчей, прошлых overlay-правок или догадок расходится с моим **свежим архивом**, ориентироваться нужно **только по архиву**.

## Как со мной работать

* **Я не разработчик**
* мне нужны **конкретные правки по файлам**
* без абстрактной теории
* без “архитектуры ради архитектуры”
* если делаешь изменения, давай **один cumulative zip**
* **не мелкие patch zip**
* **не полный архив проекта**
* в cumulative zip должны быть:

  * все актуальные файлы на замену
  * **один новый handoff txt**

## Рабочий режим

* основной режим: **`npm run dev`**
* `npm run build` — только как **smoke-check**
* сначала нужно:

  1. открыть мой свежий архив
  2. быстро проверить реальную структуру проекта
  3. подтвердить фактами:

     * где root `package.json`
     * как запускается dev
     * где frontend
     * где backend
     * что уже React/Vite
     * what is still legacy
     * как сейчас устроено extension
  4. после этого **сразу переходить к правкам**

## Что реально сделано в R8

### 1. Рефералы

Исправлен реальный UI-баг в разметке:
* в `public/app.html` и `frontend/src/legacy/legacyBody.html` у блока referrals не хватало закрывающего `</div>` после `refActionsCol`
* из-за этого `refMsg`, `Promoter details` и `Invited users` визуально уезжали внутрь верхнего flex- ряда и создавали большую пустую зону под ссылкой
* структура выровнена: верхний ряд теперь нормально закрывается, а нижние referral-блоки идут ниже по карточке

Снижен спам по `/api/referral/stats`:
* в `public/app.js` и `frontend/src/legacy/legacyApp.ts`
  * добавлен более жёсткий throttle/debounce
  * если уже есть свежий кэш, новый авто-запрос не запускается
  * окно кэша увеличено с ~3.5 сек до ~8 сек
* это должно заметно уменьшить `429 Too Many Requests` от фронтового самоддоса

### 2. GM/GN панель

Приведены fallback-тексты к более нормальному виду:
* `Random 1` → `Quick 1`
* `Random 10` → `Batch 10`
* `Apply` → `Use preset`
* `Clear ALL` → `Reset all`
* `Copy all` → `Copy view`
* `Best mode: OFF` → `Best: saved`

Правый блок тоже приведён к safe copy-only логике:
* бейджи теперь более чистые: `Fast copy`, `Tone + preset`, `Best + guard`
* описания больше не обещают unsafe insert-логику

### 3. Extension themes / wallpapers

Для сайта (tab Extension Themes):
* в `public/app.js` и `frontend/src/legacy/legacyApp.ts`
  * `setExtView()` больше не делает полный перерендер грида, если пользователь уже в том же view
  * добавлены `markExtThemeSelection()` и `markExtWallpaperSelection()`
  * теперь при выборе темы/обоев активная карточка обновляется сразу, без полной тяжёлой перерисовки
* это снижает лаги во вкладке extension themes

Для popup extension:
* в `extension/popup.js`
  * добавлен `themeSignature` guard, чтобы одинаковая тема не применялась по кругу повторно
  * уменьшен лишний churn при повторных storage refresh
  * усилено различие между обычной темой и wallpaper/custom views
* в `extension/popup.css`
  * фон и карточки стали менее “всегда чёрными”
  * ослаблен тёмный overlay
  * `ghost`-кнопки больше не выглядят как постоянные danger-кнопки
  * разделение `primary / secondary / ghost` стало заметнее

### 4. Генерация

В `index.js` сделан ещё один проход по качеству:
* усилены более живые GM/GN фразы в базовых пулах
* удалена часть самых роботных концовок
* повышена вероятность эмодзи во всех режимах (`min/mid/max`)
* quality scoring теперь сильнее любит:
  * тёплые короткие пожелания
  * более бытовые слова
  * нормальные короткие ночные/утренние формулировки
* и сильнее режет роботные хвосты типа `that reads fine` / `that is the line`

## Что проверить первым делом в новом чате

### 1. Рефералы

Проверить:
* исчезла ли большая пустота под referral link
* стало ли меньше 429 по `/api/referral/stats`
* отображается ли referral link стабильно после `Load stats`

Если 429 всё ещё есть:
* смотреть, где ещё вызывается `refreshRefStats()` / `scheduleRefStatsRefresh()`
* смотреть `applyLang()` / `MutationObserver` / автопереключения вкладок

### 2. Extension themes

Проверить:
* после **полного reload extension** реально ли подхватываются темы и обои из сайта
* стал ли popup визуально светлее и чище
* уменьшились ли лаги в самой вкладке Extension themes на сайте

Если popup всё ещё “почти чёрный”:
* проверить значения в `chrome.storage.local`:
  * `gmx_ext_theme`
  * `gmx_ext_view`
  * `gmx_ext_wp`
  * `gmx_ext_custom_bg_global`
* проверить, не работает ли пользователь со старой не перезагруженной сборкой extension

### 3. Генерация

Проверить все режимы:
* **min** — реально короткий
* **mid** — нормальный дефолт
* **max** — чуть полнее, но без мусора

Если текст всё ещё кажется “не как живой X-ответ”:
* следующий проход делать уже отдельно и глубже именно по:
  * `composeReply()`
  * `styleFlavor`
  * per-style / per-tone voice
  * локальный `Best` score на сайте

## Известные возможные хвосты

* `ERR_CONNECTION_REFUSED` по `/api/...` и `/assets/...` — это обычно backend не запущен, а не новый баг UI
* если в браузере висит старая версия extension, можно видеть старое поведение до полного reload extension
* `content.js` и прочий старый extension-мусор в архиве всё ещё лежит, **но мы его не удаляли специально**
