# Dev: известные несоответствия и как проверять

## Быстрые ссылки для проверки (локально)

Используй **`127.0.0.1`**, не `localhost` — иначе на Windows часто `ERR_CONNECTION_REFUSED` (IPv6).

| Что | URL |
|-----|-----|
| Бэкенд (канон HTML со диска) | http://127.0.0.1:10000/app |
| Корень бэкенда (редирект на `/app`) | http://127.0.0.1:10000/ |
| Здоровье API | http://127.0.0.1:10000/api/health |
| Версия API | http://127.0.0.1:10000/api/version |
| Vite dev (тот же shell, что на 10000, для `/` и `/app`) | http://127.0.0.1:5173/app |
| Vite корень → подставляется `/app` с бэкенда | http://127.0.0.1:5173/ |
| Аркада (канон `arcade.html` с бэкенда) | http://127.0.0.1:10000/arcade и http://127.0.0.1:5173/arcade |
| React-мост (отдельная сборка `/bridge`) | http://127.0.0.1:5173/bridge |

Запуск обоих процессов: из корня репозитория **`npm run dev`** (бэкенд + Vite).

## Канон вёрстки

- **Канон** — то, что отдаёт бэкенд с диска: `http://127.0.0.1:10000/app` (файл `public/app.html` + статика из `public/`).
- **Vite** `:5173` не является отдельным «дизайном»: тот же HTML должен подставляться с бэкенда.
- **Один origin для dev:** в `frontend/.env.local` задай `VITE_API_ORIGIN=http://127.0.0.1:10000` (или порт бэкенда после `npm run dev`, если он сдвинулся). `vite.config.ts` читает его через `loadEnv`, чтобы middleware (подстановка HTML) и прокси били в тот же хост, что и клиентский API. Переменная `GMX_BACKEND_URL` в shell имеет приоритет.

## Порт Vite занят

- Если `5173` занят, Vite возьмёт следующий свободный (например `5174`) — смотри строку `Local:` в консоли. Канон по умолчанию — `5173`, когда порт свободен.

## Что ломало `:5173/app` (исправлено в `frontend/vite.config.ts`)

1. **`Accept` без подстроки `text/html`** (например `*/*`) — запрос не считался «документом», срабатывал fallback Vite → отдавался `frontend/index.html` → React **AppShell** вместо каноничного shell. Исправление: учитывать `Sec-Fetch-Dest: document`, пустой Accept и `*/*`.
2. **Корень `/`** — бэкенд отвечает **302** на `/app`; при ручном редиректе и узком `Accept` можно было получить не тот контент. Исправление: для документа на `/` запрашивать у бэкенда сразу **`/app`** (query сохраняется), редиректы при `fetch` — `follow`.
3. **`/arcade` на Vite** — без подстановки с бэкенда открывался React `ArcadePage` из `index.html`, а не **`public/arcade.html`**, как на `:10000`. Исправление: для документных GET на `/arcade`, `/arcade.html`, `/arcade/*` подставлять ответ бэкенда (редиректы → `arcade.html`).
4. **Заголовки ответа** — при копировании HTML с бэкенда не переносятся `Content-Encoding` / `Content-Length` / `Transfer-Encoding` / `Connection`, если тело уже собрано как строка (иначе возможен рассинхрон с реальным телом).

Если снова увидите «не тот» UI на 5173: откройте сначала `:10000/app` и сравните; заведите запись в этом файле (дата, URL, заголовки запроса при необходимости).
