GMXReply R60 - dev port recovery pass

This pass only targets the local dev startup crash / restart loop.

Root issue fixed:
- tools/dev-run.mjs previously tested backend port availability against 127.0.0.1
  while the real backend binds to 0.0.0.0.
- On Windows this could falsely look "free", then index.js failed on listen
  with EADDRINUSE and dev-run entered a restart loop.
- frontend 5173 could then remain busy too from the previous half-broken run.

Files changed:
- tools/dev-run.mjs
- index.js

What changed:
1) dev-run now checks port listeners through system PID lookup first.
2) backend port is validated against the actual bind host 0.0.0.0.
3) frontend/backend ports try to kill old listeners, then cleanly fall back.
4) frontend is not started until backend /api/health is really up.
5) if backend port changes on restart, frontend is restarted too.
6) shutdown now preserves a non-zero exit code during listen/startup failures.

Local check:
- close old terminals from previous broken run
- run: npm run dev
- expected:
  - no endless EADDRINUSE loop
  - if 10000 or 5173 is occupied, dev-run either frees it or picks a fallback port
  - frontend starts only after backend health is reachable
