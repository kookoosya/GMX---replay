WHAT WAS BROKEN RIGHT NOW
1) Extension popup connect could fail with "Failed to fetch"
2) X inline GM/GN buttons were rendering, but placement was unstable and insert could fail / hit stale composer
3) In local React+Vite dev, extension API requests could point at the frontend dev server instead of backend

ROOT CAUSE FOUND
- site_sync was storing apiBase = location.origin
- when the site is opened through local React/Vite (127.0.0.1:5173 / localhost:5173), the extension then reuses 5173 as API base
- popup/content/background fetches from the extension context can fail when they hit the Vite dev server instead of the backend API
- content.js also kept binding to a specific composer node; X often rerenders that node, so clicks could target a stale box
- current inline placement logic still leaned on dock-right absolute positioning, which is fragile on X

- extension/content.js
- extension/popup.js
- extension/background.js
- extension/site_sync.js
- extension/manifest.json

WHAT WAS CHANGED
1) Local API base hardening
- In popup/content/background normBase(), local frontend ports now normalize to:
  http://127.0.0.1:10000
- This keeps extension API calls pointed at backend during React+Vite local dev
- Production domains still normalize exactly as before

2) site -> extension sync fix
- extension/site_sync.js now stores backend apiBase when the site runs on local frontend ports (like 5173)
- bestEnabled sync tail no longer references an out-of-scope constant for localStorage writes

3) X button insert reliability

  - whole-text execCommand insert

  - final direct DOM fallback
- insert now verifies that text actually appeared before reporting success
