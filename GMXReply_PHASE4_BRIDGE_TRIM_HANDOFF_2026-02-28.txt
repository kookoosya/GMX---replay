GMXReply Phase 4 correction handoff
Date: 2026-02-28

Why this patch exists
- Phase 3 build was technically fine.
- The real problem was product direction drift: /bridge started pretending to be the whole app before those screens were actually migrated.
- This patch cuts that back.

What this patch changes
- App.tsx:
  - narrows React bridge scope to three real states only: Overview, Referrals, Admin
  - keeps direct URL support for /bridge, /bridge/referrals, /bridge/admin
  - removes fake placeholder routes for GM/GN/Leaderboard/Themes/etc
  - keeps existing auth, refresh, usage, and admin/referral loading logic
- TopNav.tsx:
  - now shows only Overview + Referrals + Admin (Admin only when handle is admin)
  - no fake full-app navigation

What stays as-is
- main.tsx dynamic loading from Phase 3 stays in place
- vite chunk splitting from Phase 3 stays in place
- legacy /app remains the source of truth for the full product UI

Why this is the correct direction
- React bridge should expose only screens that are actually migrated
- Referrals and Admin are already real React business screens
- We stop spending time building fake shell routes and go back to controlled migration

Next correct phase
- Improve Referrals screen itself:
  - cleaner KPI wording
  - promoter / unlock detail cleanup
  - better separation of personal stats vs invited-users table
- After that, harden Admin screen UX
