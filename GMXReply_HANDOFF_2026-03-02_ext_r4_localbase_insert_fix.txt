Source of truth used:
- Bac 2.zip (project base)
- r3 extension patch was reviewed, but this pack fixes the regressions from that pass

What was actually broken:
1) Local extension connect was made worse by forcing any local origin to 127.0.0.1:10000.
   - In React+Vite dev, the working API base can be the Vite origin (ex: 127.0.0.1:5173) because Vite proxies /api.
   - If backend port shifts, forcing 10000 breaks popup connect and status.
2) X inline insert was still brittle when local lists were empty / stale.
3) Button clicks could steal focus from the X composer before insert.

What this pack changes:
- extension/popup.js
  - keeps any localhost/127 origin as-is (does NOT rewrite 5173 -> 10000)
  - tries the stored local origin first, then probes local ports 10000..10020 as fallback
  - keeps prod fallback after local candidates
- extension/content.js
  - keeps any localhost/127 origin as-is
  - safer editor readback (prefers X data-text nodes)
  - safer clear/replace pipeline for the X composer
  - prevents focus-steal on GM/GN button press (pointerdown/mousedown preventDefault)
  - if saved list is empty but extension session exists, GM/GN now fall back to direct API generation instead of dead-ending
- extension/site_sync.js
  - sync now prefers window.__GMX_API_ORIGIN when the React/Vite shell exposes it, otherwise uses location.origin
- extension/manifest.json
  - version bumped to 1.0.13

Files in this pack:
