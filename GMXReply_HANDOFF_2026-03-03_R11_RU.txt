SECURITY / АНТИ-ПОДМЕНА ОПЛАТЫ (предложения, без внедрения в этом паке):
- Любая активация Pro должна происходить ТОЛЬКО после server-side проверки on-chain tx:
  - backend читает chain RPC, проверяет: to-address (allowlist), amount>=price, token/chain, tx status, confirmations
  - backend сам пишет "pro=true" для handle, фронт не решает ничего
- На фронте:
  - никогда не хранить "адрес получателя" как изменяемое значение из localStorage/URL
  - получатель/chain/price должны приходить с backend (signed config)
- CSP в ответах сайта (запрет inline script где возможно), строгий allowlist доменов
- Верификация bundle/receipt: серверная подпись ответа (HMAC/ed25519) чтобы нельзя было подменить JSON в пути
