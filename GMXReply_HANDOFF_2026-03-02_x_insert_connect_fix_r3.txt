WHAT WAS BROKEN
1) X inline GM/GN buttons were visible, but insert still failed (toast: "Could not insert.")
2) Popup connect still showed "Connect failed: Failed to fetch" in local dev in some runs

ROOT CAUSES FIXED IN THIS PACK
1) content.js insertion flow was too destructive:
   - old fallback path used box.textContent = "" and box.textContent += ...
   - on X composer this can wipe editor scaffold / inner nodes
   - after that, later insert attempts can fail or get reverted

2) popup.js local connect was still too brittle:
   - if apiBase was empty/default, popup could still try the wrong base first
   - local dev should prefer backend 127.0.0.1:10000 before production fallback

CHANGES IN THIS PACK
- extension/content.js
  - rewrote setTextboxText() into a safer multi-stage insert pipeline
  - removed destructive root-level box.textContent clears
  - added safer editor helpers:
    - normalizeEditorText
    - readEditorText
    - focusEditorBox
    - emitEditorInput
    - buildPasteEvent
    - findWritableLeaf
    - writeEditorLeaf
  - insert order now:
    1. execCommand(insertText)
    2. synthetic paste event

    5. per-char fallback without nuking editor root
  - message listener now explicitly returns false (sync response path is clear)

- extension/popup.js
  - added LOCAL_DEV_BASE = http://127.0.0.1:10000
  - added base candidate fallback logic
  - connect now tries candidate bases in order and stores the first successful base
  - status refresh now probes across candidate bases and self-heals stored apiBase when needed

- extension/manifest.json
  - version bumped to 1.0.12
