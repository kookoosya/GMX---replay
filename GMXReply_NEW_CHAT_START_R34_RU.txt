GMXReply — NEW CHAT START (RU) — R34

Baseline / Source of truth

Source of truth = этот свежий рабочий архив.
Если что-то из старых сообщений, старых патчей, handoff-файлов или догадок расходится с этим архивом, ориентироваться нужно только по этому архиву.

Что уже сделано в R34

1. Собран полный рабочий архив в одном корне `Backend/` (с `.git`).
2. Внутрь подмешаны актуальные split-папки: `frontend/`, `assets/`, `public/`.
3. Обновлён `index.js` до более свежей версии из рабочей папки пользователя (там уже есть более короткий `min` режим генерации).
4. Из архива убраны лишние runtime-файлы и мусор, который только раздувает размер и не нужен для замены:
   - `data.sqlite-wal`
   - `data.sqlite-shm`
   - `logs/`
   - `mnt/`
   - `frontend/dist/`
   - `*.bak*` backup-файлы
5. В `extension/popup.js` починен самый опасный баг с обоями: `.webp` больше не читается как текст/SVG; добавлена нормализация ID (`ext_*` / `ext_free_*` -> `extv3_*`) и безопасный fallback на `/bridge/assets/...`.
6. В `extension/popup.css` смягчён fit для больших обоев (`contain`), чтобы большие картинки не обрезались так агрессивно.
7. В `frontend/src/legacy/legacyApp.ts` зафиксированы актуальные free-константы (8 / 8 / 4 / 4) и сохранён referral-step (+1 каждые 3 eligible refs, потом +1 каждые 4).
8. В user-facing текстах обновлены формулировки: убраны старые упоминания про `100` и `first 10 skins`, заменена раздражающая строка про “Paid but Pro isn’t active?”.
9. Добавлены мягкие CSS-правки для читаемости при обоях и для более аккуратного поведения на широких экранах.

Что ещё НЕ доведено до конца

1. Тема / обои ещё не унифицированы полностью между:
   - legacy `/app`
   - React/bridge
   - extension popup
   Сейчас самый опасный баг в popup исправлен, но полная унификация ID и ассет-путей всё ещё нужна.
2. В `legacyApp.ts` и частично в `public/app.js` по-прежнему есть тяжёлая и старая логика тем/обоев, которую нужно дочистить и упростить.
3. Нужно сделать полную ревизию рендера вкладок `Themes` и `Extension Themes`:
   - где идут лишние перерисовки
   - где старые тексты
   - где UX всё ещё тяжёлый
4. Нужно решить структуру canonical assets:
   - выбрать один master-source
   - убрать дубли между `assets/`, `frontend/public/assets/`, `public/bridge/assets/` без поломки runtime
5. Arcade в архиве уже есть как направление, но это не финальная вшивка. Отдельный `GMXReply_Bac3_Arcade_REACT_VITE_PHASE64_MASTER_READY.zip` по-прежнему можно использовать как reference для следующего шага.
6. Генерация всё ещё требует отдельной доработки `mid/max/best/repeat guard`.

Как работать в новом чате

1. Сначала открыть этот свежий архив и быстро подтвердить фактами:
   - где root `package.json`
   - как запускается `npm run dev`
   - где backend
   - где frontend
   - что уже React/Vite
   - что всё ещё legacy
   - как сейчас устроено extension
2. Сразу после этого перейти к ревизии ошибок по файлам, а не по догадкам.
3. Приоритет в новом чате:
   - (1) до конца добить `Themes / Extension Themes`
   - (2) унифицировать theme/wallpaper ID + ассеты
   - (3) проверить реальное применение обоев в extension
   - (4) только после этого добивать Arcade
   - (5) потом генерация, payment/security, финальный cleanup
4. Если делаются правки, нужен один cumulative zip + один новый handoff txt.

Что нельзя ломать

- Нельзя возвращать GM/GN кнопки внутрь X
- Нельзя делать DOM-inject в x.com
- Extension должен оставаться safe copy-only
- Нельзя ориентироваться на старые патчи, если они расходятся с этим архивом
